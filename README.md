# わたし推し活(旧: 自分満たしカード)

「31日間チャレンジ達成カード」の続きのツール。毎日の小さな「好き」(やってみたこと)を記録して、あとから見返し、「私って、こんなことが好きなんだ」の発見につなげる30日間。スタンプや達成数は、あえて置かない(集めることが目的にならないように)。

- 期間: **2026年11月1日(日)〜11月30日(月)の30日間**(全員共通。Code.gs と app.js の `PROGRAM_START_DATE` / `PROGRAM_LENGTH`)
- 受講生はアカウント登録不要。SkipFマイページの「呼び名」と同じ名前を入れるだけで開始でき、同じ名前で続きから再開できる
- 「今日やってみたこと」を自由記述(300文字まで)。**1日に何件でも**記録できる。押し忘れた日も、日付を選んで遡って書ける。書き直し・削除もできる
- **11/12のプレ講座以降**は、「五感や気持ちも記録してみる」のチェックを入れると、印象に残った五感(嗅覚・触覚・味覚・聴覚・視覚、いくつでも)と「そのとき、どう感じた?」を添えられる(どちらも任意)。日付は `app.js` の `SENSES_START_DATE`
- 記録には写真を1枚添えられる(任意)。書き直しで差し替え・取り外しができ、記録を削除すると写真もドライブのゴミ箱に入る。保存先はGoogleドライブの「自分満たし写真」フォルダ(長辺1280pxに縮小、リンクを知っている人は見られる設定)。写真は記録と一緒に「みんなの『好き』」にも表示される。スプレッドシートの `records` シートの右端 `photo_id` 列に入る(既存のシートには、最初の保存時に見出しが自動で足される)
- タブは「わたしの記録」(書く欄+自分の記録)・「みんなの投稿」・「管理者」の3つ(2026-10-18に、みんなの投稿をタブに分けた)
- 「わたしの記録」で、自分の記録を日付ごとに見返せる(件数・日数と、よく感じた五感も表示)。それぞれの記録に、もらったリアクションの数と「💬 コメント N件を見る」が出て、開くとお礼や返信を書ける
- 書いた内容は**名前つき**で「みんなの投稿」に表示される(五感・気持ち・写真も含む)。見られるのは**同じ期(3期・4期など)のメンバーと運営だけ**(2026-10-18に、匿名から名前つきに変更)
- 「みんなの投稿」では、リアクション4種類(💗いいね / 🤝わかる / ✨元気もらった / 🌱やってみたい)と、コメント・コメントへの返信(1段)ができる。コメントにも名前が出る(自分は「あなた」、記録した本人には「(記録した人)」)。自分の記録にはリアクションできない
- **運営**: 名簿で期を「運営」にした人は、すべての期の記録を見て、いいね・コメントできる(「すべて / 3期 / 4期」で絞り込み)。運営の記録は「運営・名前」としてすべての期に表示される。なりすまし防止のため、運営の名前でログインするときだけ管理者の合言葉(ADMIN_PIN)が必要
- 以前の「交流」タブは2026-10-16に廃止し、コメントは記録につける形にした(comments シートの `post_id` は記録のID。`feed_posts` シートはもう使わない)
- 管理者タブ(同じURL)で、全員の記録数・日数と全記録(期・コメントつき)を見られる。不適切な記録・コメントは「非表示にする」で、メンバーの画面から消せる(記録は本人の画面には残る)
- 11/1より前に開くと「11/1(日)にオープンします」の画面だけが出る。11/1になると、自動で通常の画面に切り替わる
- 上部の「チャレンジシート / わたし推し活」で、2つのツールを行き来できる。ログインした名前は、同じブラウザなら、もう一方の名前欄に引き継がれる
- 書きかけの記録は端末に自動保存される(画面を閉じても消えない)

### 期(グループ)

- 期は、スプレッドシートの `roster` シート(呼び名 → 期)で判定する。管理者タブから、まとめて登録(貼り付け)や、1人ずつの登録ができる
  - まとめて登録は、「呼び名,期」を1行ずつ貼る形のほか、「3期」の行の下に呼び名を1行ずつ並べる形(マイページの一覧をそのまま貼る形)にも対応
  - 名簿と入力した名前は、全角/半角・大文字/小文字・空白・記号(〜 ♡ など)・頭の「◯期」・末尾の「ちゃん/さん/くん」を無視して比べる(`normalizeName`)。それで一致すれば自動で確定。似ているだけ(どちらかがもう一方の先頭と一致)の人や、名簿にない人は**「確認待ち」**になる。管理者タブの「期の確認待ち」に候補つきで並ぶので、運営がボタンで確定する(入力した名前で名簿に登録される)
- 期が決まっていない受講生(確認待ち・名簿にない人)は、自分の記録は書けるが、「みんなの『好き』」は見られない(「期を確認しています」などと出る)。その人の記録も、期が決まるまでは誰にも(運営にも)表示されない。期が決まると、さかのぼって表示される

## 技術構成

ビルド不要の静的サイト(HTML / CSS / 素のJavaScript)。GitHub Pagesにそのままpushするだけで公開できる。

- データはGoogle Apps Script経由でGoogleスプレッドシートに保存(`students`・`records`・`comments`・`roster` のシート。自動で作られる。スタンプ方式だった頃の `posts` シートと、交流タブの `feed_posts` シートは使わない)
- みんなの投稿のAPIは、記録とコメントに名前と期を付けて返す(受講生のIDは返さない)。見られる範囲(同じ期+運営)は、サーバー側で絞り込む
- 管理者の合言葉は **スクリプトプロパティ `ADMIN_PIN`** に保存する(GitHubには載らない)。サーバー側で確認するので、合言葉なしでは投稿の名前も、非表示操作もできない
- スプレッドシートのセルはすべて「文字列」の書式。`=` で始まる投稿が計算式として動いたり、日付に勝手に変換されたりしない

## セットアップ

### 1. Googleスプレッドシート + Apps Script

1. [sheets.google.com](https://sheets.google.com) で**新しい**スプレッドシートを作る(名前は例: 「自分満たしカード DB」。31日間チャレンジのスプレッドシートとは別のファイル)
2. 「拡張機能」→「Apps Script」を開き、中身を全部消して [`apps-script/Code.gs`](apps-script/Code.gs) の内容をすべて貼り付けて保存(Command + S)
3. 左の歯車「プロジェクトの設定」→ 一番下の「スクリプト プロパティ」→「スクリプト プロパティを追加」
   - プロパティ: `ADMIN_PIN`
   - 値: 管理者タブに入る合言葉(31日間チャレンジとは別のものがおすすめ)
4. 右上「デプロイ」→「新しいデプロイ」→ 歯車(種類の選択)→「ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
5. 「デプロイ」→ 初回は許可の画面が出るので許可する → 表示された**ウェブアプリのURL**(`.../exec`)をコピー

### 1-b. 写真の保存の許可

Apps Script のエディタで、関数の一覧から `authorizeDrive` を選んで「実行」を押し、Googleドライブへのアクセスを許可する(初回だけ)。これで、写真の保存先フォルダ「自分満たし写真」が作られる。

### 1-c. 期(グループ)の登録

公開後に、管理者タブ →「期(グループ)の設定」で、受講生の呼び名と期を登録する。マイページ側から期つきで案内できるようになったら、`roster` の運用はやめられる。

### 2. 設定ファイル

[`config.js`](config.js) の `https://script.google.com/macros/s/xxxx/exec` を、コピーしたURLに書き換える。

### 3. 手元での確認(本物のスプレッドシートは使わない)

```bash
node scripts/serve.cjs --today=2026-11-05 --admin-pin=test1234
```

[http://localhost:8091/?today=2026-11-05](http://localhost:8091/?today=2026-11-05) を開く(URLの `?today=日付` で、画面上の「今日」を変えて見られる。見え方が変わるだけで、書き込みの日付の判定はサーバー側なので、不正はできない)。`Code.gs` をそのまま疑似スプレッドシート上で動かすので、サーバー側のプログラムも含めて確認できる(`/__reset` でデータを初期化、`/__set?today=2026-11-10` でサーバー側の「今日」を変更)。

### 4. 公開前の動作確認(本物のスプレッドシートで)

11/1より前は日付の判定で書き込めないので、確認の間だけ、サーバーの「今日」を11/5にする。

1. Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」に `TEST_TODAY` = `2026-11-05` を追加する
2. 登録・書く・書き直し・リアクション・非表示・取り消しなどを確認する(`=1+1` のような文字で始まる投稿が、計算式にならず、そのまま文字で入ることも確認する)
3. **確認が終わったら、必ず `TEST_TODAY` を削除する**(残っていると、本番の日付がずれる)
4. スプレッドシートの `students` と `records` のシートから、確認用の行を削除する(1行目の見出しは残す)

### Code.gs を更新したときは

Apps Scriptのコードを直したら「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →「バージョン: 新バージョン」→「デプロイ」(「新しいデプロイ」はURLが変わるので使わない)。

### style.css / app.js を更新したときは

`index.html` 内の `style.css?v=1` / `app.js?v=1` / `config.js?v=1` の数字を1つ増やす(キャッシュを無視して読み直させるため)。

## デモ環境(?demo=1)

公開URLの末尾に `?demo=1` を付けると、デモ用のスプレッドシート(本番とは別のファイル)につながる。クライアントへの説明や研修で、本番のデータを汚さずに触ってもらうためのもの。

- `config.js` の `DEMO_URL` に、デモ用Apps ScriptのウェブアプリURLを入れる
- デモ用のApps Scriptには、本番と同じ `Code.gs` を貼り、スクリプトプロパティ `ADMIN_PIN`(デモ用の合言葉)と `TEST_TODAY`(`config.js` の `demoToday` と同じ日付。いまは `2026-11-14`)を入れる
- 画面上部に「デモ環境です」と出て、日付は `demoToday` として動く(五感の欄も出る)
- 端末に覚える内容(ログイン中の受講生など)は本番と別(`jmc_demo_` で始まるキー)。チャレンジシートとの名前の引き継ぎは、デモでは使わない

## GitHub Pagesへのデプロイ

1. GitHubで新しいリポジトリを作る(Public。例: `jibun-mitashi-card`)
2. このフォルダをpushする(`git remote add origin ...` → `git push -u origin main`)
3. リポジトリの `Settings` → `Pages` → `Source: Deploy from a branch` / `main` `/(root)` で保存
4. 数分後、`https://(アカウント).github.io/(リポジトリ名)/` で公開される

## 配るURL

LINEで配る場合は、URLの末尾に `?openExternalBrowser=1` を付ける。

例: `https://(アカウント).github.io/jibun-mitashi-card/?openExternalBrowser=1`
